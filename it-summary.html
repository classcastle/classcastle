Classcastle IT & Privacy Summary

For IT administrators and school district buyers

Data Collected

Student data (during active room only):

  • Name (entered by student when joining — no account or email required)
  • Online status (whether the student is currently connected)
  • Current URL (the page the student is viewing during the room session)

Teacher data:

  • Email address (for Supabase authentication)
  • Room codes and room settings
  • Activity logs (room creation, student joins, URL navigation)

Data retention: Student data is only kept while a room is active. When a room is closed, student records are deleted. Teacher data persists for account management and analytics.

Deployment Steps

  1. Get the extension ID: Find Classcastle's ID (acfkgmbemlolnjcnhfokelioeienonoi) and store listing under Admin → Deployment in the teacher app.
  2. Force-install through policy: Add the extension ID to ExtensionInstallForcelist in the Google Admin console for ChromeOS and Chrome, or push it via Intune or GPO for Edge.
  3. Allow the connection: Safelist hduyofdbpspjcuwvackd.supabase.co in your web filter or firewall so room connections aren't blocked on the school network.
  4. Verify on a test device: Confirm the icon appears pinned and can join a test room, then roll out to the rest of the fleet with the same policy.

Security & Privacy

  • All data encrypted in transit (HTTPS)
  • Teachers only see their own rooms and students
  • Students can only access content the teacher approves via URL navigation
  • No browsing history collection beyond current URL during active room
  • No external code execution — all extension code is local
  • Supabase RLS policies ensure data isolation between teachers
