    Connect an app with Classcastle OAuth

    Create an OAuth app here, then use its client ID, client secret, scope, and redirect URL in your integration. The client secret is shown only once, so store it securely.

    How the redirect works

    1. Your app sends the user to the Classcastle authorization endpoint.
    2. The user signs in and approves the requested scope on the consent page.
    3. Classcastle sends the user back to the exact Redirect URL registered for your OAuth app.

    Classcastle does not keep the user on the Classcastle website after consent. Register your app's callback route, such as https://your-app.example.com/oauth/callback, and make sure it matches exactly.

    Using Supabase as your OAuth client

    For a Supabase project, register this callback URL as the OAuth app's Redirect URL:

    https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback

    Then configure the Supabase custom provider with the values in View Supabase setup guide. After Supabase receives the authorization response, it redirects to the URL in your Supabase Auth client request.

    Read Supabase's custom OAuth provider documentation for the provider setup and callback flow.

    Testing sign-in from Dev Labs

    The Continue with Classcastle button returns to this Dev Labs page after authentication. In production, the return URL is the current Dev Labs page; in a local preview, it is the current local page. Add the relevant URL to Supabase Auth's allowed redirect URLs.

    • https://devlabs.classcastle.org/
    • http://127.0.0.1:4173/devlabs/index.html for the local preview
